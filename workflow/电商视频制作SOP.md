# 电商视频制作SOP

版本：2026-10-26-v2。用户明确要求总结并在后续沿用。仅约束本项目视频制作；用户新要求优先，不移植其他项目身份、私人素材、账户或批准记录。

## 当前入口与边界

- 本会话为花洒视频唯一执行Owner，不另建重复工程或Owner。
- 当前阶段以 `production/花洒视频/制作-v1/工程/manifest.json` 和 CapCut 实际工程为准；旧阶段说明不是当前状态。
- 拍摄执行单：`production/花洒视频/拍摄准备/手机实拍拍摄脚本.md`。商品权威：`products/主推花洒/商品事实与制图要求.md`，最新偏好：`workflow/项目偏好与当前状态.md`。
- 已有三条参考仅完成覆盖全时段的每0.5秒抽帧查看；未连续观看、未直接听音。证据：`production/视频参考分析/2026-10-25/细读/`。不得将此记录改称“完整看完”。

## 1. 开工与能力核实

先确认目标观众、观看目的、现有素材/文案/声音状态、输出比例/时长和交付范围；已有答案复用，只集中询问实质缺口。检查已有成果，从最早受影响阶段续作。

开工早期核实工具是否支持连续看听，分别记录：连续观看、抽帧（间隔和覆盖范围）、音轨转录、OCR、直接听音。互不替代；解码完整不代表已看听。无法完成的检查标未完成，不编造PASS。工具受阻先查 `/Users/USER/.codex/LOCAL_BLOCKERS.md`；不为普通剪辑研发工具、安装大型模型或启用付费API。

## 2. 素材与工程

通常保留原件、不修改；用户明确授权清理本轮原件和参考时，先核对最新工程依赖、共享用途与精确清单，再按授权清理。使用最小必要结构：原始素材索引、工程配置、中间预览、最终输出；视频成果放 `production/花洒视频/`，不覆盖既有商品图片。

制作开始后只维护一份明确的当前制作单/Manifest，记录素材路径、来源及限制、内容、时长/尺寸/帧率/音轨、可用区间与排除项、source_in/source_out和成片时间映射、字幕、必要组件来源、版本和检查欠项。不为每个动作另建报告，不多份“最新最终版”。

## 3. 制作顺序

素材与能力核对 → 选有效镜头、确定信息顺序 → 完整粗剪 → 确定配音/BGM及精剪时序 → 连贯代表片段包装 → 扩展整片 → 实际导出检查 → 集中返修交付。

实拍广告不强制口播先行：先让商品动作与水型展示成立；需要AI配音时在精剪和字幕定时前固定文案、音轨。BGM确定后尽早纳入节奏。先有完整可播放粗剪，不先精做几秒才判断整片是否成立。内部检查自主完成，不增设用户逐段审批；样片授权止于样片，整片授权推进至完整交付。

## 4. 实拍与动效

真实商品优先：外观、三档水型、切档与红针动作以实拍及用户事实为准；3D和生成图不充当实物真值。不用AI补造水流、孔位、红针动作、内部结构或测试效果。

默认先用实拍、硬切、大字字幕、必要局部放大/三档分屏。保留动作开始、变化和结果的观看时间，不用重复镜头、照片慢推或无关装饰撑时长。不强制Fred/Remotion，不同时建立多个制作栈。按实际任务读取Skill，不整库加载，也不凭名称猜能力/API。

确需成熟组件时，先看原预览、源码和依赖，真实复用并追溯来源→实现→调用→导出；不把手写近似版冒充复用。先检查最长文字、动作中间态、危险媒体切换和相邻接缝，再扩展整片。同一对象跨场景保持位置、裁切、层级及媒体时钟连续，不靠白闪遮掩跳位。

竖屏裁切按商品、手指、按键与水流共同取景，不机械中心裁切；运动中不切掉关键动作。不继承其他项目Logo、默认版式或账户。

## 5. 声音、字幕和配乐

保留原片声音，不要求用户先加字幕/BGM或剪短。水声、按键声有表达价值时留出空间；不得制造假现场或假功能音效。

如有原声，保留字头字尾及必要呼吸，不重复降噪/变速/全轨增益；ASR错词改字幕，不据此切正常原音。听不清或不确定的切点先保留。J/L cut基于真实声音。全局音轨变化后统一重映射字幕、镜头和动效一次。

字幕少而清晰、大字突出重点，不加细小脚注，不重复色名/档名；避开中央红钮、下方按键、孔口、水流及平台界面区域。按实际配音校正文字和分句，核对数字、名称、标点。在约360—390px手机宽度检查关键镜头和最长字幕。

AI配音先核实际可用工具、声音和费用，不预先承诺已具备；付费先确认。BGM用用户指定或有可核使用权的音乐，不默认截用参考音乐或其他项目私人音轨；音乐不盖旁白，已有BGM不重复叠加。平台原生音乐方案保留无BGM干净版，不承诺流量。

## 6. 导出与验收

当前暂定竖屏1080×1920、30fps；最终按明确要求调整。记录原片与合成帧率，不把补重复帧称为增加运动细节。图片JPG限制不套用于视频交付。

检查实际导出MP4：完整播放、声音存在、字幕/数字/顺序、裁切遮挡、动作中间态、相邻接缝、白闪/重复起播、原声自然度、同步和音乐覆盖、原尺寸及手机可读性、首尾完整。商品真实性另对实拍核验。

完整解码仅为技术检查；抽帧不证明连续运动流畅，ASR/波形/响度不证明听感。连续看听未完成时明确列欠项，不能称整片视听验收通过。内部通过与用户/客户接受单列，不把可导出当成已接受。

## 7. 返修与交付

锁定反馈版本，集中列意见和保留范围，局部修改只补验改动及相邻接缝；全局音轨/时序/结构变化才扩大检查。“提前/后移”以同一原片源时刻比较。保留有效成果，不随意换风格、重做整片或重复全量渲染。

交付实际可播放MP4、必要字幕、可编辑工程或明确工程入口、简短版本说明和未解决项；封面按本次范围提供。保护原件、字体、源码、历史版本，不擅删、不上传新目的地、不付费、不外发或公开发布；已授权常规本地制作自主推进。

完工仅记录有证据的主要缺陷、修复/返修轮数、可读取耗时及下次一个具体改进；不估算不可读Token或保证节省比例。临时意见留本期，明确通用偏好才更新规范。


## 8. 2026-10-26 本轮经验：CapCut 配音、配乐与收口

### 已验证有效的方法

- 原生主时间线空白时，本机1026通过素材右键“根据选中素材新建时间线”建立了时间线02。拖放残影不算导入成功，不能照失败操作反复拖。此结论不自动适用于其他版本。
- 本地 SRT 导入后，在素材卡片点“+”才加入时间线；双击仅预览。选中橙色文本→右侧“朗读”→语言/音色，才是生成旁白入口。选中蓝色音频的“声音效果→音色”属于变声，两者不能混用。
- 全片统一声音时，选中全部目标文本，确认每个片段的选中边框、音色卡片名称及高亮，再执行一批朗读。星形收藏按钮不等于选中音色。先前面板坐标随布局改变，必须以当次截图确认，不能沿用旧坐标盲点。
- 本机“开始朗读”会新增音频，不会可靠地替换旧音频。生成前锁定旧旁白，完成后逐段核对新音频的数量、起点、长度及启用状态；旧旁白停用以防叠播。不能靠“已点击同一音色”宣称听感一致。
- 实拍喷雾替换 AI 错误水型有效。原三档 AI 喷雾持续生成7孔而实际应为6孔；第二次同类失败后停止重复花钱，改用实拍。中格仅做二维旋转、缩放与取景，不能声称改变了真实拍摄视角。
- 保留用户认可的2.5秒片段、转场和局部构图，返修只改受影响部分。背景先裁切/清理首帧再考虑生成，不以大量禁词代替商品保真检查。

### 本轮碰壁与固定纠正

- **未经验收就重复导出：错误。** 当前用户明确“先验收、不导出”时，只保存原生工程。即使免费、即使为了检查，也不能另导出审阅版。只有用户后续明确允许才导出。
- **配音同名或批量生成不证明同声：** 先做一句，用户确认实际声音后才扩展；如果用户明确要求全部替换，则一次执行该范围，完成后仍标“待听感验收”。记录选中名称、生成批次和旧轨处理，不猜根因、不编造实际听音。
- **会员音乐到导出才发现：** 库内未见钻石不保证可免费导出。本轮 Pop Summer Upbeat Main 被原生导出门禁标 Pro。先核账号可用性；无法不导出核实时标 UNKNOWN，不为验证突破用户“不导出”限制。可商用筛选与免费资格是两回事；不付费，不擅换用户选曲。
- **BGM 盖人声：** 本轮 Motivational Corporate11 曾为+16.2 dB，五句旁白为0 dB且未静音；已将音乐调至−18 dB并让用户试听。该值只是本轮起点，不作为所有曲目的固定标准。先查轨道静音、片段停用、音量、时间位置和库内试听状态，避免直接重新生成配音。
- **音乐尾巴制造黑帧：** 本轮音乐起于0.3秒，结束22.3秒，视频22秒；对齐起点后恢复22秒。加歌后必须检查整体时长和尾帧，不只看波形。
- **耗时生成与重复付费：** 一次只测试一个明确镜头，提示词/参考图和费用先给用户检查；未知任务结果先查任务ID，不盲目重提。详细 Prompt 不能锁定孔位、手指、按钮和软管；功能细节不符立即弃用。用户要求5秒时不擅用10秒。
- **把抽帧、解码和音量检查当成视听验收：错误。** 检查记录必须注明实际覆盖和方法。没有直接听音，就不能说“声音统一”“人声清晰”或“混音通过”。

### 节约时间的执行清单

1. 复用当前工程和已认可镜头，先读唯一 Manifest，不重建制作栈、不重复读全库。
2. 一个批次完成：文本/音色选择确认→生成→旧轨停用→数量与时序→用户在工程试听。未通过不全量渲染。
3. 音乐由用户选；核会员状态、增益、起止和淡出，再进行联合试听。普通改音量不重新生成旁白、不换剪辑结构。
4. 自动保存后记录工程名、时间线、音色、BGM及欠项。只有明确授权导出时才输出一个明确版本；不再积累多个“最终版”。
5. 收口按依赖清理而非按日期清理：旧编号的底片可能仍是最新工程必需。先保存精确清单及依赖存在性/哈希，再删除授权内非必需文件；不修改 CapCut 私有工程JSON，不清共享缓存，不删除共用商品图库。
